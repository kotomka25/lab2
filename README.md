# Лабораторная работа №2
## Исследование уязвимостей веб-приложений и методы их устранения на Python

### Цель
Создать локальное веб-приложение, продемонстрировать эксплуатацию двух уязвимостей OWASP Top 10 и исправить их.

### Реализованные уязвимости
1. **SQL Injection (SQL-инъекция, OWASP A03:2021 — Injection).** В `app.py` логин и пароль напрямую подставляются в SQL-строку. Специально сформированный ввод может изменить условие запроса и обойти проверку пароля.
2. **Broken Access Control / IDOR (OWASP A01:2021 — Broken Access Control).** В `app.py` сервер проверяет факт входа, но не проверяет, имеет ли текущий пользователь право просматривать профиль с указанным ID.

### Структура проекта
- `app.py` — уязвимая версия приложения.
- `app_patched.py` — исправленная версия.
- `exploit.py` — учебный скрипт демонстрации атак; принимает только localhost/loopback URL.
- `patches/security.patch` — diff с исправлениями.
- `requirements.txt` — зависимости.

### Требования
Python 3.9 или новее.

### Установка и запуск (Windows)
Откройте терминал в папке проекта:

```bash
py -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

Приложение будет доступно по адресу http://127.0.0.1:5000

На Linux/macOS:
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m pip install -r requirements.txt
python app.py
```

При первом запуске автоматически создаётся `lab.db` с двумя тестовыми пользователями:
- alice / alice123 (ID 1)
- bob / bob123 (ID 2)

Это демонстрационные пароли, не используйте такой способ хранения паролей в реальных системах.

### Часть 2. Демонстрация эксплуатации
Не закрывая сервер, откройте второй терминал в папке проекта:

```bash
python exploit.py
```

Ожидаемый результат на уязвимой версии:
- SQL Injection: вход без правильного пароля;
- IDOR: чтение профиля пользователя Bob с ID 2 после входа.

Скрипт намеренно ограничен локальными адресами. Не меняйте это ограничение для проверки чужих систем.

### Часть 3. Исправление
Остановите сервер `Ctrl+C`. Запустите исправленную версию:

```bash
python app_patched.py
```

В другом терминале снова выполните:

```bash
python exploit.py
```

Ожидаемый результат:
- SQL-инъекция больше не позволяет войти без правильного пароля;
- доступ к `/profile/2` от имени Alice отклоняется с HTTP 403.

Исправления:
- SQL Injection: используются placeholders `?` и отдельный список параметров. Ввод пользователя больше не интерпретируется как часть SQL-кода.
- IDOR: перед выдачей профиля сравнивается запрошенный `user_id` с ID пользователя из сессии. При несовпадении возвращается HTTP 403.

### Применение diff
Файл `patches/security.patch` содержит изменения относительно `app.py`. Для применения к копии исходного файла:

```bash
git apply patches/security.patch
```

Патч меняет `app.py` на защищённый вариант. Перед применением сохраните исходную копию. Альтернативно можно просто запускать `app_patched.py`.

### Вывод
В ходе лабораторной работы создано локальное Python веб-приложение с двумя уязвимостями. Написан скрипт на Python, который демонстрирует SQL Injection и IDOR. Затем уязвимости устранены параметризованным SQL-запросом и проверкой прав доступа. Повторный запуск скрипта показывает, что исправления блокируют продемонстрированные атаки.
